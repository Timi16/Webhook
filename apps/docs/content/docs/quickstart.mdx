You need a server reachable over HTTPS (port 443 or 8443) that can receive a `POST`, and `curl`.

Set two variables so the commands below can be pasted as they are:

```bash
export API=https://api.webhookdev.xyz         # the Webhook API
export DASHBOARD=https://webhookdev.xyz    # the origin the API trusts for browser requests
```

## 1. Create an account and an API key

The quickest way is the dashboard: sign up, open **API keys**, click **Create key** and copy the key
it shows you. [Authentication](/docs/authentication) explains permissions, expiry and IP limits.

To do it from the terminal instead: accounts are session based, so these two calls keep a cookie.
Every later call uses the API key.

```bash
curl -c cookies.txt -X POST $API/auth/signup \
  -H "Origin: $DASHBOARD" -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"a long passphrase"}'

curl -b cookies.txt -X POST $API/v1/api-keys \
  -H "Origin: $DASHBOARD" -H "Content-Type: application/json" \
  -d '{"name":"my server"}'
```

Signing up emails you a 6-digit code, and the account is locked until you confirm it. Run this
between the two calls above, with the code from the email:

```bash
curl -b cookies.txt -X POST $API/auth/verify \
  -H "Origin: $DASHBOARD" -H "Content-Type: application/json" \
  -d '{"code":"123456"}'
```

The key-creation response contains `key`, starting with `whk_test_`. It is shown once; store it now.

```bash
export KEY=whk_test_...
```

The examples from here on come in three flavours. The Node.js ones use the built-in `fetch`
(Node 18 or newer); the Python ones use [`requests`](https://pypi.org/project/requests/). Both read
the same two environment variables, `API` and `KEY`.

<Callout type="warn">
  Passwords need at least 10 characters. The `Origin` header is required on these two calls because
  they use a cookie; calls made with an API key do not need it.
</Callout>

## 2. Create an endpoint

<Tabs groupId="language" persist items={['curl', 'Node.js', 'Python']}>
<Tab value="curl">

```bash
curl -X POST $API/v1/endpoints \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/webhooks/stellar","description":"production"}'
```

</Tab>
<Tab value="Node.js">

```js
const res = await fetch(`${process.env.API}/v1/endpoints`, {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({ url: "https://example.com/webhooks/stellar", description: "production" }),
});
const { endpoint, secret } = await res.json();
console.log(endpoint.id, secret); // store the secret now: it is not shown again
```

</Tab>
<Tab value="Python">

```python
import os, requests

res = requests.post(
    f"{os.environ['API']}/v1/endpoints",
    headers={"Authorization": f"Bearer {os.environ['KEY']}"},
    json={"url": "https://example.com/webhooks/stellar", "description": "production"},
)
body = res.json()
print(body["endpoint"]["id"], body["secret"])  # store the secret now: it is not shown again
```

</Tab>
</Tabs>

The response contains the endpoint's `id` and its `secret` (`whsec_...`). The secret is also shown
only once. Your server uses it to [verify signatures](/docs/verifying-signatures).

This sends a `test.ping` event and returns the result of the first attempt:

```json

```

## 4. Watch a wallet

<Tabs groupId="language" persist items={['curl', 'Node.js', 'Python']}>
<Tab value="curl">

```bash
curl -X POST $API/v1/watches \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{
    "walletAddress": "G...",
    "label": "Shop checkout",
    "endpointId": "ENDPOINT_ID",
    "assets": [{ "code": "USDC", "issuer": "GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5" }],
    "amountRule": { "kind": "min", "amount": "10" },
    "memoRule": { "kind": "present" }
  }'
```

</Tab>
<Tab value="Node.js">

```js
const res = await fetch(`${process.env.API}/v1/watches`, {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({
    walletAddress: "G...",
    label: "Shop checkout",
    endpointId,
    assets: [{ code: "USDC", issuer: "GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5" }],
    amountRule: { kind: "min", amount: "10" },
    memoRule: { kind: "present" },
  }),
});
const { watch, warnings } = await res.json();
console.log(watch.id, warnings);
```

</Tab>
<Tab value="Python">

```python
res = requests.post(
    f"{os.environ['API']}/v1/watches",
    headers={"Authorization": f"Bearer {os.environ['KEY']}"},
    json={
        "walletAddress": "G...",
        "label": "Shop checkout",
        "endpointId": endpoint_id,
        "assets": [{"code": "USDC", "issuer": "GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5"}],
        "amountRule": {"kind": "min", "amount": "10"},
        "memoRule": {"kind": "present"},
    },
)
body = res.json()
print(body["watch"]["id"], body["warnings"])
```

</Tab>
</Tabs>

The response includes `warnings`. `ACCOUNT_NOT_FOUND` or `NO_TRUSTLINE:USDC` mean the wallet cannot
receive that asset yet; the watch is still saved, so you can fix the wallet afterwards.

<Callout type="error">
  `walletAddress` is the public address, starting with `G`. If you paste a secret key (`S...`) the
  request is refused. Never send a secret key to any service.
</Callout>

### Rules you can set

| Field | Options |
| --- | --- |
| `assets` | One or more of `{ "code": "XLM", "issuer": null }` or `{ "code": "...", "issuer": "G..." }`. |
| `amountRule` | `{ "kind": "any" }`, `exact`, `min` or `max` with `amount`, or `range` with `min` and `max`. Amounts are decimal strings; edges are inclusive. |
| `memoRule` | `{ "kind": "any" }`, `present`, `absent`, or `equals` with `value` and `type` (`text`, `id` or `hash`). |
| `senderAllowlist` | Addresses allowed to pay. Empty means anyone. |
| `eventTypes` | `payment.received` (default). Add `payment.rejected` to be told about payments that fail the rules. |

## What to do in your handler

1. [Verify the signature](/docs/verifying-signatures) using the raw request body.
2. Check whether you have already processed this `Webhook-Id`. If so, answer `200` and stop.
   See [retries and duplicates](/docs/retries-and-duplicates).
3. Record the event, answer `200`, then process it.
